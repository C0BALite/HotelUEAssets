# MHS-13 — тестовая сцена очередей ресепшн

## Как проверить

1. Открой `Content Browser → Test → MHS13 → L_MHS13_ReceptionQueues` и нажми **Play**. Гости появляются по двум маршрутам и подходят к общей стойке.
2. Наведи камеру на первого гостя в зоне обслуживания Check-In или Check-Out и нажми **E**. Гость уйдёт по боковому проходу. Следующий гость той же очереди займёт его место.
3. Нажми **G**, чтобы переключить допуск новых Check-In гостей. После закрытия допуска NPC, который уже шёл к очереди, может в неё вступить. Check-Out продолжит работать. Вместимость каждой очереди в сцене — четыре гостя.
4. Оставь гостей ждать. Check-In гость уходит после 90 секунд с момента вступления в очередь. Отсчёт для гостя прекращается при начале обслуживания. У Check-Out лимита ожидания нет.

`BP_MHS13_Guest` подгружает локальный `BP_MHC_Test` как внешний вид. При отсутствии сборки используется простой цилиндр. Перемещение выполняет отдельный `Character` с `AIController`. Отдельный набор анимаций ходьбы для MetaHuman в прототип не добавлен.

## Подключение других механик

В каждой зоне стоит свой экземпляр `BP_MHS13_ReceptionQueue`. Режим задаётся свойством `IsCheckIn`. `Capacity`, `PatienceSeconds`, `EntryPoint`, `ServicePoint`, `SlotOffset` и `ExitPoint` можно настроить на экземпляре. Точки заданы в мировых координатах, а `SlotOffset` — шаг от места обслуживания к хвосту очереди.

| Задача | Узел Blueprint |
|---|---|
| Синхронизировать допуск Check-In с наличием чистой комнаты и режимом приёма | `SetIntakeAllowed`. Источник спавна проверяет `CanSpawnGuest` перед созданием гостя. |
| Добавить гостя, когда он подошёл к входу очереди | `TryEnqueue(Guest)`. Возвращает `Accepted`. Заполненная очередь и повторное добавление дают отказ. |
| Получить текущий состав | `GetFirstGuest`, `GetQueueCount`, `GetQueueCapacity`. |
| Начать разговор | `BeginService(Guest)`. Гость должен быть первым и уже подойти к месту обслуживания. Событие `OnServiceStarted` передаёт время ожидания в секундах. |
| Освободить место после передачи ключа или расчёта | `CompleteService(Guest)`. Завершает обслуживание только активного гостя. |
| Удалить гостя по внешней причине | `RemoveGuest(Guest)`. Освобождает место и продвигает очередь. |

События для подписки — `OnGuestJoined`, `OnServiceStarted`, `OnServiceCompleted`, `OnGuestTimedOut` и `OnQueueChanged`. `OnGuestTimedOut` также передаёт `WaitSeconds`. Это данные для будущих систем удовлетворённости и рейтинга.

Для интеграции оставь `AutoSpawnForTest` выключенным. В тестовой сцене этот флаг включает генерацию гостей, клавиши **E** и **G**, а также отправку обслуженного гостя к выходу. При выключенном флаге дальнейший маршрут обслуженного гостя задаёт подписчик `OnServiceCompleted`.

## Проверка

Оба Blueprint скомпилировались в UE 5.8 без ошибок и предупреждений. Автоматический PIE `MHS13.ReceptionQueues` прошёл в рабочем проекте с `BP_MHC_Test` и в отдельном проекте с тремя ассетами MHS-13. Проверены вместимость, подход и продвижение NPC, ввод **E** и **G**, таймаут Check-In, остановка таймера при обслуживании, ожидание Check-Out и повторные вызовы. Порог 90 секунд проверен через выставление времени вступления в прошлое. PIE запускался без рендера.
